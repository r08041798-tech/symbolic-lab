# v0.4
Short ambiguous messages and greetings are routed locally. Token budgets 48/112/192, 45-second generation cap, 180-second load cap, stop button, worker termination and repetition detection. Light uses SmolLM2 360M; Better uses Qwen2.5 0.5B Instruct ONNX q4 (786 MB weights). Both still experimental, no quality guarantee. No browser inference benchmark was performed. Original custom skills remain. Tests cover pure guards; browser worker cancellation and model inference require device testing.

## v0.4.1
Fixed unescaped apostrophe in the conversation system prompt which prevented the module from parsing. Added versioned module URL and service worker cache revision, plus regression import and greeting tests.

## v0.5 mobile performance
Worker stream batching at 250 ms, progress throttle, no smooth scroll or mobile autofocus, capped DOM history, reduced phone context and output budget, idle worker termination, release on model switch/hidden tab/new chat/cache clear, optional cancel on typing enabled on phones, 135M q8 fallback. These mitigate but cannot guarantee absence of OS-level resource contention. Actual phone benchmark pending.

## v0.6 indexed intelligence
Default mode never calls the generative model. Six capability profiles, 31 curated topic records, hierarchical domain paths and aliases, SHA-256 checked catalog and individually loaded topic chunks, session-only version-keyed answer reuse, topic follow-ups and two-topic comparisons. Optional neural fallback requires explicit selection. Alias matching is deterministic, not a learned semantic embedding system; unsupported questions abstain. The curated notes have not been independently fact-checked for this release. No phone benchmark performed.

## v0.7 weighted query planner
Five numerical domains; typed slots, restricted arithmetic expression trees, recursive dependency planning with bounded alternate paths, cost and structural weights, minimum-weight propagation, lazy SHA-256 domain packs, explicit evidence and assumption display, consistency checks, local rule counters used for route ranking. These counters are correlated formula checks, not independent truth or accuracy calibration. Natural language extraction is grammar-based; coverage is limited. Unrecognized requests fall back to v0.6. No browser/device benchmark performed.

## v0.9 weighted model routing and acquisition
Combines the unfinished v0.8 learning path with opt-in automatic model selection. Task-specific prior scores, conservative device tiers, completion feedback and one model per request. Indexed/derived knowledge and acquired IndexedDB alias records take precedence. Teacher produces bounded JSON definitions; schema-valid output remains unverified, never executable. Worker released immediately. Unknown RAM uses conservative defaults, and RAM thresholds are heuristics not real free-memory measurements. No direct weight slicing, factual validation or actual browser inference benchmark yet.

## v0.10 sparse pretrained neural lab
Uses shibatch/tinyqwen3moe2m (MIT, revision 4047166), a TinyStories-trained Qwen3-MoE validation checkpoint. Direct Safetensors range index; refuses non-206 responses, never uses full checkpoint fallback. Learned top-1 expert gating, per-expert matrix slices, float32 tensor cache capped at a user-selected fraction, shared layer dependencies, LRU expert eviction, causal attention/KV cache and limited greedy decoding. Report retained parameter count, cumulative unique fetched weights, bytes, requests, and routing probabilities (not confidence). Cumulative bytes can exceed model size because of repeated loads. Runtime retains below 100% of checkpoint tensors; this is not a cap on total JS heap. Source checkpoint download blocked in execution environment, so actual remote layout, CORS/range support, tokenizer parity and output equivalence are unverified. Unit tests use synthetic weights, not live model inference. The lab is a story continuation experiment, not a general factual assistant. Dense mode remains separately available by explicit user choice.
